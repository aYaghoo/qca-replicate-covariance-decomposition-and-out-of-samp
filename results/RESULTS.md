# Results: Covariance Decomposition and Out-of-Sample Forecasting

All numbers below come from simulated data (Scenario B, described next), generated by
`python -m exp.exp1_covariance_forecasting` and `python -m exp.exp2_portfolio_evaluation`
at commit `92add27`. Earlier results in this file came from a different simulator; see
[Earlier results (Scenario A)](#earlier-results-scenario-a) at the end.

## Setup

### Data-generating process (Scenario B, `src/data_simulation.py`, since `52035fa`)

- N = 20 stocks, K_max = 7 latent factors, 10 sectors, T = 250 days after a 250-day burn-in.
- Latent factor and idiosyncratic variances follow a HAR(1, 5, 22) process in logs,
  calibrated to daily US stock moments (median daily vol: market 1.0%, style factors 0.5%,
  idiosyncratic 1.4%).
- Loadings are tied to the simulated firm characteristics used to build the factor portfolios.
- The **observed** daily covariance is a realized covariance from M = 78 intraday returns, so
  it carries Wishart measurement noise around the latent matrix. All forecasts are scored
  against this observed matrix (after cleaning), not against the latent one.

### Experiment configuration (identical in Exp 1 and Exp 2)

| Parameter | Value |
|---|---|
| Assets N / factors K_max / sectors | 20 / 7 / 10 |
| Days T | 250 |
| Rolling window | 100 |
| First OOS index | 122 (window + 22) |
| OOS days | 128 |
| LASSO λ grid size (`n_alphas`) | 3 |
| Seed | 42 |

### Units

- **Simulator and Exp 1: percent.** Daily returns are in percent (daily sd ≈ 1.8), so
  covariance entries are in percent². Exp 1 L2 errors are in percent² units.
- **Exp 2: decimals.** Forecasting runs in percent, as in Exp 1. Before the portfolio stage,
  `to_decimal_units` in `exp2_portfolio_evaluation.py` converts once: returns ÷ 100, and the
  observed (random-walk) and forecast covariance matrices ÷ 100². The portfolio functions in
  `src/portfolio.py` expect decimals. Annualized σ and LPSTD below are reported in percent
  (decimal × 100 × √252).

observed covariance. Relative values are model ÷ random walk (RW); below 1 means the model
beats RW.

### Findings: Exp 1

- **Every model beats the random walk**, by 10–17% on seed 42 and 13–18% averaged over five
  seeds. The observed matrices carry measurement noise, so yesterday's matrix is a noisy
  forecast. HAR-type smoothing over 1, 5, and 22 days reduces that noise.
- **K = 1 forecasts best** in this simulation, and the log (matrix-log) variant is slightly
  better than the non-log one for every K in the five-seed means. Differences among
  K = 3, 5, 7 are small.
- **LASSO and adaptive LASSO are nearly indistinguishable** (differences in the third or
  fourth decimal).
- These comparisons use one universe size (N = 20), a short window (100), and a 3-point λ grid.
  No significance test (for example Diebold–Mariano) has been run, so small gaps between
  models should not be read as rankings.

## Experiment 2: minimum-variance portfolios

Daily rebalanced minimum-variance portfolios built from each one-step-ahead forecast
(seed 42, 128 OOS days). Realized returns are the simulated daily stock returns in decimals.

- **Unconstrained**: min w′Σw s.t. 1′w = 1 (closed form).
- **Restricted**: also total short positions ≤ 30% and |wᵢ| ≤ 20%.
- **Long-only**: 0 ≤ wᵢ ≤ 20%.

The restricted and long-only problems are solved with cvxpy/CLARABEL. A day whose solve fails
(solver error, or a status other than optimal/optimal_inaccurate) would use equal weights and
be counted in `n_fallback`. **No portfolio fallbacks and no forecast fallbacks occurred.**

### Findings: Exp 2

- **Every model portfolio has lower realized volatility than the RW portfolio** in the
  unconstrained and restricted regimes (12.7–13.4% vs 14.5–15.0%). In the long-only regime
  the gap is small (14.0–14.1% vs 14.5%).
- **Turnover is far lower for the model portfolios**: about 0.005–0.011 per day vs
  0.034–0.082 for RW. The RW forecast is yesterday's noisy realized matrix, so its weights
  move a lot from day to day.
- The lowest-σ model is K1_LASSO (unconstrained, restricted) and K3_AdaLASSO (long-only),
  but differences among models are a few tenths of a percentage point on 128 days of one
  seed and are not tested for significance.
- LPSTD is computed by `src/portfolio.py` (RMS of negative *centered* portfolio returns).
  `src/metrics.py` has a different definition; which one is intended is an open question.

## Earlier results (Scenario A)

Before commit `52035fa`, `src/data_simulation.py` used a different simulator ("Scenario A"),
and this file reported results from it: RW mean L2 ≈ 0.0003, with every model **46–62× worse**
than RW, and annualized portfolio volatilities of 64–69%. Those numbers do not describe the
current code, and the conclusion they supported (RW wins) is reversed under Scenario B.

Why Scenario A favored the random walk:

- **No measurement noise.** The "realized" covariance was the latent matrix itself (plus a
  1e-6 ridge), so yesterday's observed matrix was yesterday's true matrix.
- **Near-constant variances.** Volatilities followed a smooth deterministic recursion,
  `vol_t = 0.95·vol_{t−1} + 0.05·|shock| + 0.002` with shock sd 0.005 (and similarly for
  residual variances), so the matrix changed very little from one day to the next. With
  no burn-in, the series also drifted slowly toward its stationary level.
- Together these made the RW forecast nearly exact. Any estimated model could only add
  estimation error.

Scenario A also had no stated units. The old Exp 2 percentages came from treating its
returns as decimals.

Scenario A is not re-run here because that simulator is no longer in the current code (it
remains in git history at `bd70bdd`).

## Notes carried over from the earlier version (not re-verified)

These implementation notes were in the previous version of this file. They were not
re-checked for this rewrite.

1. The paper's 430×430 realized-kernel matrices (2006–2011) are not public. All results here
   use simulated data.
2. SMB uses a 50th-percentile size breakpoint.
3. The gross-profitability factor is long low-GP, short high-GP, as the paper defines it.
4. `decompose_covariance` adds a 1e-6 ridge to Σ_f before inverting it.
5. In the log variant, the day/week/month averages are of the matrix logarithms.
